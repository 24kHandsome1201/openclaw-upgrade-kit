# Adjacent open-source agent feedback (raw)

_As of 2026-03-09. Focus: open-source or open-ish agent ecosystems adjacent to OpenClaw._

## OpenHands
### Facts
- OpenHands publicly encourages users to submit feedback and help create an open corpus of coding-agent examples (“Share-OpenHands”).[1]
- The public issues page on 2026-03-09 shows demand around automation, scalable MCP usage, conversation visibility, SDK-created conversation inheritance, and search subagents.[2]

### Positive signals
- Strong star count and active issue flow suggest high interest.[2]
- The project explicitly treats user feedback as training/evaluation data, which is a strong product-learning loop.[1]

### Complaints / unmet needs
- Users are asking for better conversation durability and visibility (“messages can be lost”, conversation invisibility in UI).[2]
- MCP/integration scalability is already an issue at the product layer.[2]
- There is repeated pressure for more automation, better settings inheritance, and plan/task coordination.[2]

### Implication
Open-source agent users increasingly expect not just “an agent” but a platform with durable sessions, automation hooks, scalable tool integration, and good visibility into state.

## Cross-project signal
Across OpenClaw/OpenHands-style projects, the shared pain points are:
- session durability
- tool routing/integration quality
- visible planning/progress state
- upgrade safety and configuration sanity
- permission/security posture that is understandable by non-experts
