# Routing Loop

Use this loop when deciding how to route work across skills.

1. Define the current task shape.
2. Identify the dominant evidence source.
3. Start with `openclaw-manus` if the task is mixed or still unclear.
4. Switch to a specialized skill if the next high-value step is clearly in one lane.
5. Re-evaluate after each meaningful stage.
6. Fall back to `openclaw-manus` when the task broadens again.

## Common routing outcomes

- logs / status / config -> `openclaw-ops`
- current sources / comparison -> `openclaw-research`
- implementation / validation -> `openclaw-coding`
- README / setup / runbook review -> `openclaw-docs`
- mixed planning + execution -> `openclaw-manus`
