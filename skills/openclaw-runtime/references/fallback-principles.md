# Fallback Principles

Fallback should be simple and predictable.

## Core rule
When in doubt, use `openclaw-manus`.

## Use fallback when
- task classification is unclear
- the task spans multiple lanes equally
- the current specialized skill is no longer dominant
- a specialized skill is unavailable in the runtime

## Good fallback behavior
- explain the fallback briefly
- preserve task continuity
- keep the next step operational

## Bad fallback behavior
- falling back without explaining why
- staying in a specialized skill after the task has become mixed
- using fallback to avoid inspection or verification
