# Working Mode

This file defines the preferred working mode for `openclaw-research` on non-trivial research tasks.

The purpose is to keep research work:
- staged
- source-backed
- easy to delegate when subtopics are independent
- reviewable before conclusions are accepted

## Core principle

Do not treat research as one long brainstorm.

Instead:
1. define the current research stage
2. define the exact question for that stage
3. define what evidence must be gathered
4. execute or delegate the scoped research work
5. review the findings before integrating conclusions
6. move to the next stage only after uncertainty is clearer

## Stage-first research mode

Typical research stages:
- question framing
- source strategy
- primary-source gathering
- comparison and conflict resolution
- synthesis
- conclusion and recommendation

Each stage should answer:
- what exact question is being answered?
- what source type is required?
- what deliverable should the stage produce?
- how will weak evidence or uncertainty be marked?

## Verifiable deliverables rule

Every meaningful stage should produce at least one verifiable research artifact.

Examples:
- source list
- fact summary tied to sources
- comparison note with explicit evidence
- freshness check result
- recommendation with stated uncertainty

Avoid vague stage endings such as:
- "seems differentiated"
- "looks better"
- "probably still true"

## Delegation rule for research work

Research work may be delegated when subtopics or source lanes are independent.

Good delegation candidates:
- one competitor vs another competitor
- official docs review vs release note review
- benchmark writeup vs source collection
- one sub-question vs another independent sub-question

Avoid parallel delegation when:
- subtasks depend on the same unresolved source conflict
- multiple workers would synthesize the same conclusion independently
- freshness is highly time-sensitive and results may diverge mid-task

## Parent-agent responsibility

When research work is delegated, the parent agent should:
1. define the exact question and source expectations
2. define the allowed scope of inference
3. require source-backed findings
4. review the findings before integrating conclusions
5. resolve overlap or contradiction across delegated outputs
6. verify that final claims match the cited evidence
7. summarize only after evidence quality is acceptable

## Evidence-before-conclusion rule

Do not accept delegated research output only because the conclusion sounds reasonable.

Before integration:
- inspect the cited sources
- confirm facts are separated from inference
- check whether freshness was handled correctly
- verify that uncertainty is marked where evidence is incomplete

## Keep-synthesis-tight rule

A good staged research flow usually looks like:
- frame one question
- gather the strongest sources
- compare only what matters to the decision
- synthesize a supported conclusion
- continue only if another question remains unresolved

## Working-mode success criteria

The working mode is functioning well when:
- research tasks are broken into explicit stages
- each stage leaves behind a real evidence artifact
- delegated work has clean question boundaries
- conclusions are reviewed before acceptance
- uncertainty and source quality remain visible
